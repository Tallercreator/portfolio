# Портфолио

Astro 7 + React, статическая сборка, CSS на токенах. Два языка: RU в корне, EN под `/en`.

```bash
npm run dev      # http://localhost:4321
npm run build    # сборка в dist/
npm run preview  # посмотреть собранное
```

## Куда что класть

| Что | Где |
| --- | --- |
| Текст кейса, RU | `src/content/cases/ru/<slug>.mdx` |
| Текст кейса, EN | `src/content/cases/en/<slug>.mdx` |
| Картинки кейса | `src/assets/cases/<slug>/` |
| Видео кейса | `public/video/<slug>/` |
| Резюме PDF | `public/cv.pdf` |
| Строки интерфейса | `src/i18n/ui.ts` |
| Стилистика | `src/styles/tokens.css` |

Slug файла = адрес страницы. `travel.mdx` → `/case/travel` и `/en/case/travel`.
Файлы RU и EN одного кейса должны называться одинаково, иначе переключатель языка уведёт на 404.

Если в `title`, `outcome` или `summary` есть двоеточие — обернуть значение в одинарные кавычки, иначе YAML не разберёт строку и сборка упадёт.

## Добавить картинку в кейс

```mdx
import Figure from '../../../components/Figure.astro';
import статусы from '../../../assets/cases/travel/statuses.png';

<Figure
  src={статусы}
  alt="Статусная модель заявки: восемь состояний и переходы между ними"
  caption="Заявка проходит восемь состояний. Красным — тупики, из которых сотрудник не мог выйти сам в бумажном процессе."
/>
```

`width` — `text` (в колонку текста), `wide` (по умолчанию, шире колонки), `full`.
Две картинки рядом — `FigureGrid` с вложенными `Figure`.

Astro сам жмёт и отдаёт `webp`/`avif` в нужных размерах и ставит `loading="lazy"` — ничего оптимизировать руками не надо. Складывать в `src/assets`, а не в `public`: в `public` оптимизация не работает.

Подпись важнее картинки: она говорит, куда смотреть. Картинка без подписи — дриббл-шот.

## Раздел «Древние картинки мои»

Некликабельная галерея внизу главной. Картинки кладутся в `src/assets/gallery/` — и всё, больше ничего делать не надо.

- Порядок — по имени файла, управляется префиксами: `01-`, `02-`
- Форматы png, jpg, webp, avif. Сжимать не нужно, Astro сделает сам
- Пока папка пустая, раздела на сайте нет
- Анимированные гифки сюда не кладём, они потеряют анимацию — им место в `public/`

Ссылок внутри раздела нет намеренно, а `alt` у картинок пустой: они декоративные, и скринридеру важен только заголовок раздела.

## Превью кейса для главной

Обложка карточки задаётся в шапке файла кейса, а файл лежит там же, где остальные картинки — в `src/assets/cases/<slug>/`.

```yaml
cover: ../../../assets/cases/travel/cover.png
coverAlt: 'Экран заявки на командировку со статусом согласования'
```

Путь считается от самого MDX-файла, поэтому `../../../` — это выход из `cases/ru/` в `src/`. Для английской версии путь тот же: обложка у кейса одна на оба языка, отличается только `coverAlt`.

Что важно:

- **пропорции 3:2**, например 1600 × 1067. Карточка обрезает по центру, поэтому главное держи в середине кадра;
- у коротких кейсов (`compact: true`) карточка 16:9, но исходник всё равно давай 3:2 — обрежется само;
- `coverAlt` не украшение: на карточке нет подписи, и для скринридера alt — единственное описание. Пиши, что на экране, а не «превью кейса»;
- если обложки нет, карточка не ломается — вместо картинки покажет строку результата. Кейс без единого скриншота выглядит нормально.

## Добавить видео в кейс

Записи экрана кладутся в `public/video/<slug>/`, а не в `src/assets` — Astro оптимизирует картинки, но не видео, из `public` файл отдаётся как есть.

```mdx
import Video from '../../../components/Video.astro';
import постер from '../../../assets/cases/travel/statuses-poster.png';

<Video
  src="/video/travel/statuses.mp4"
  poster={постер}
  caption="Заявка проходит восемь состояний. На записи — путь от черновика до согласованной."
  mode="loop"
/>
```

`mode="loop"` — короткий немой цикл на 5–15 секунд, запускается сам. `mode="controls"` — длинная запись, человек включает её сам.

Что делает компонент:

- не грузит файл, пока запись не подъехала к экрану;
- ставит на паузу, когда она ушла из виду;
- при `prefers-reduced-motion: reduce` не запускает ничего и показывает постер;
- если браузер заблокировал автоплей, показывает кнопку воспроизведения.

Постер желателен: он же первый кадр, он же замена видео при выключенном движении.

### Как записывать

- Окно фиксированной ширины, 1280 или 1440 — не на весь экран, иначе текст будет мелкий.
- Один ролик — одна мысль. 5–15 секунд. Лучше три коротких, чем одна минута.
- Без звука. Курсором водить медленно, без рывков.
- Только демо-данные. Запись цепляет намного больше лишнего, чем скриншот: подсказки, счётчики уведомлений, соседние строки в списках, боковое меню.

### Как сжимать

`ffmpeg` в системе нет, ставится так:

```bash
brew install ffmpeg
```

Дальше по одному файлу — MP4 без звука, шириной не больше 1600:

```bash
ffmpeg -i исходник.mov -vf "scale='min(1600,iw)':-2" -an -c:v libx264 -crf 26 -preset slow -movflags +faststart public/video/travel/statuses.mp4
```

WebM опционален, он легче процентов на тридцать:

```bash
ffmpeg -i исходник.mov -vf "scale='min(1600,iw)':-2" -an -c:v libvpx-vp9 -crf 34 -b:v 0 public/video/travel/statuses.webm
```

Ориентир по весу: 10 секунд интерфейса после сжатия — это 300–800 КБ. Если вышло несколько мегабайт, поднимай `-crf`.

## Кейс без единого скриншота

Если по ОТП не согласуют интерфейсы — верстка это переживает:

- карточка на главной без `cover` показывает вместо картинки строку результата;
- схемы, диаграммы состояний и before/after процесса вставляются теми же `Figure`.

## Стилистика

Все визуальные решения — в `src/styles/tokens.css`, в два слоя: примитивы и семантика. Компоненты обращаются только к семантическому слою, поэтому смена стилистики по референсам — это правка одного файла.

Что сейчас стоит как заглушка и ждёт референсов:

- `--a-400/500/600` — акцентный цвет;
- `--font-sans`, `--font-mono` в `src/styles/base.css` — гарнитуры;
- шкала кеглей: шаг 1.2, база 17px.
